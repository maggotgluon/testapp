## Quick Start

```bash
# 1. Clone the repository
git clone <repo-url>
cd testapp

# 2. One-command setup (runs all steps)
composer setup

# This runs:
# - composer install
# - cp .env.example .env (if not exists)
# - php artisan key:generate
# - php artisan migrate --force
# - npm install --ignore-scripts
# - npm run build
```

## Manual Setup (Step by Step)

```bash
# 1. Install PHP dependencies
composer install

# 2. Copy environment file
cp .env.example .env

# 3. Generate app key
php artisan key:generate

# 4. Configure database (see below)
# Edit .env: DB_CONNECTION, DB_DATABASE, etc.

# 5. Run migrations
php artisan migrate

# 6. Install Node dependencies
npm install

# 7. Build frontend assets
npm run build

# 8. Create storage symlink
php artisan storage:link
```

## Database Configuration

### Option A: SQLite (Default for local dev)

```env
DB_CONNECTION=sqlite
```

The SQLite file at `database/database.sqlite` is already committed and contains empty tables. No additional setup needed.

### Option B: MySQL

```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=ticketflow
DB_USERNAME=root
DB_PASSWORD=
```

Create the database:
```sql
CREATE DATABASE ticketflow CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Then run migrations:
```bash
php artisan migrate
```

```env
QUEUE_CONNECTION=database   # database | redis | sync
```


### Social OAuth (Optional)

```env
FACEBOOK_CLIENT_ID=

LINE_CLIENT_ID=
```

### LINE Extended (Optional)

```env

LINE_CHANNEL_ACCESS_TOKEN=  # For LINE Messaging API push messages
LINE_WEBHOOK_SECRET=        # For validating webhook payloads
```

### Web Push (Optional)

```env
VAPID_PUBLIC_KEY=
VAPID_PRIVATE_KEY=
VAPID_SUBJECT="mailto:hello@example.com"
```

Generate VAPID keys:
```bash
php artisan webpush:vapid
```

### CRM Integration (Optional)

```env
CRM_BASE_URL=https://crm.example.com/api
CRM_TOKEN=your-bearer-token
```

If not set, all CRM sync calls are silently skipped.

### File Storage

```env
FILESYSTEM_DISK=local       # local | s3
AWS_ACCESS_KEY_ID=
AWS_SECRET_ACCESS_KEY=
AWS_DEFAULT_REGION=us-east-1
AWS_BUCKET=
```

The `uploads` disk is used for all event images and payment slips. Configure in `config/filesystems.php`.

## Admin Account Setup

Admin accounts must be created manually. The simplest approach:

```bash
php artisan tinker
```

```php
User::create([
    'name' => 'Super Admin',
    'username' => 'admin',
    'phone' => '0800000000',
    'role' => 'super_admin',
]);
```

Then log in at `/admin/login` with username `admin` and phone `0800000000`.

**Local dev shortcut:** With `APP_ENV=local`, the admin login page shows a dropdown to log in as any role without credentials.

## Known Issues / Gotchas

| Issue | Details |
|-------|---------|
| Email is synchronous | `Mail::send()` in `emailAttendees` blocks the request. Not queued. |
| No soft deletes on most models | Hard deletes are used throughout. Cascade carefully. |
| Slip image preprocessing requires GD or Imagick | The `SlipQrDecoderService` uses `imagecreate` functions — ensure PHP GD extension is enabled |
| QR decode is best-effort | Not all slip images contain readable QR codes. `needs_manual_review` is the safe fallback. |
| SQLite in dev has no row locking | `lockForUpdate()` is a no-op in SQLite. Use MySQL for testing concurrent orders. |
| `sold_count` is a denormalized counter | It's incremented on approval. If tickets are manually approved without using the controller, `sold_count` may drift. |
